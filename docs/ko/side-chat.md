# 사이드채팅

NodeOnly 서버의 채팅 입력창에서 **사이드채팅**을 열고 모델·프롬프트·에이전트를 선택한 뒤 전송합니다. PC에서는 오른쪽 패널, 모바일에서는 전체 화면 패널을 사용합니다.

처음 전송하는 시점의 원본 대화와 설정을 복사합니다. 이후 원본 채팅을 바꾸거나 수정해도 사이드 대화의 원본 맥락은 바뀌지 않으며, 사이드 답변이 원본 메시지에 추가되지 않습니다. 프롬프트의 `챗` 카드는 복사한 원본 대화, `사이드 챗` 카드는 임시 대화의 사용자 메시지와 답변을 넣습니다. 사이드 챗 카드가 없으면 실행할 때 마지막에 추가합니다. 저장된 프롬프트는 변경하지 않습니다.

전송된 요청과 에이전트의 전·후처리는 서버에서 끝까지 실행됩니다. 패널 또는 브라우저를 닫아도 계속 생성하며, 다시 접속해 세션 목록에서 결과를 확인할 수 있습니다. API 키의 기존 동시 요청 제한과 FIFO 대기열을 일반 채팅과 공유합니다. 이번 버전은 텍스트 대화, 에이전트 단계, 프롬프트 프리셋의 출력 정규식을 지원합니다. 도구·MCP·플러그인 호출과 실행형 스크립트는 사용하지 않습니다.

임시 세션은 서버의 `save/side-chats.db`에 별도로 보관합니다. 보관 수는 서버 전체 기본 3개이며 패널에서 양의 정수로 변경할 수 있습니다. 새 세션이 한도를 넘으면 마지막 활동이 가장 오래된 비활성 세션을 지웁니다. 생성·대기 중인 세션은 지우지 않으며, 전부 사용 중이면 새 세션을 거절합니다. 한도를 진행 중인 세션 수보다 작게 줄일 수도 없습니다. 서버 재시작 중 끊긴 요청은 중단 상태로 남겨 확인할 수 있고 자동 재전송하지 않습니다.

**정식 채팅으로 분기**하면 동일한 봇에 원본 대화의 복사본과 사이드 메시지 전체를 포함하는 새 채팅을 저장합니다. 메시지 ID는 새로 발급하며 마지막으로 선택한 모델·프롬프트·에이전트를 유지합니다. 이후 일반 채팅으로 이어갈 수 있고, 원본과 임시 세션은 그대로 남습니다. 선택한 프롬프트에 일반 챗 카드가 없고 사이드 챗 카드만 있으면 분기된 채팅에서 첫 사이드 챗 카드가 전체 일반 대화 기록을 제공하도록 실행 시 변환합니다.

서버 배포 전 `pnpm build`로 프런트엔드와 `dist/side-chat-runtime.cjs`를 함께 빌드해야 합니다. 기존 저장 경로와 SQLite 데이터베이스를 유지하고, 새 임시 데이터베이스도 함께 백업하십시오.
